# Задание 2: распределённая задача коммивояжёра

Распределённый генетический алгоритм на C#/.NET 9. Управляющее приложение
использует интерфейс Avalonia 11 из первого задания. Одинаковые сервисы
ASP.NET Core выполняют вычисления по HTTP и возвращают популяции и статистику.
Папка `ex2` содержит самостоятельное решение; файлы `ex1` для запуска не нужны.

## Запуск

Установите .NET SDK 9 и выполните команды из этой папки:

```bash
dotnet restore TspDistributed.sln
dotnet build TspDistributed.sln -c Release
dotnet test TspDistributed.sln -c Release
```

В первом терминале запустите сервис:

```bash
dotnet run --project src/TspWorker -c Release --no-build -- --urls http://127.0.0.1:5101
```

Во втором терминале запустите ещё один экземпляр того же сервиса:

```bash
dotnet run --project src/TspWorker -c Release --no-build -- --urls http://127.0.0.1:5102
```

В третьем терминале откройте управляющее приложение:

```bash
dotnet run --project src/TspDistributed.App -c Release --no-build
```

В окне уже указаны адреса обоих сервисов. Выберите города и параметры,
затем нажмите «Старт». С одним сервисом приложение тоже работает:
оставьте одну строку в списке адресов. «Стоп» отменяет текущие запросы
и сохраняет лучший маршрут из полученных ответов.

Для запуска на нескольких компьютерах используйте на каждом сервисе
`--urls http://0.0.0.0:5101`, а в управляющем приложении укажите их IP-адреса
и порты. Например, `192.168.1.10:5101` и `192.168.1.11:5101`.
Можно указать URL с `http://` или `https://`; для HTTPS серверу нужен сертификат.
IPv6 указывается в скобках: `[::1]:5101`. Порт обязателен.

## Распределение вычислений

Координатор создаёт по одному острову на каждый адрес. Остров содержит свою
популяцию, число завершённых поколений и зерно генератора случайных чисел.
Размер популяции в окне задаётся **для каждого острова**.

Сервис развивает популяцию блоками по заданному числу поколений.
Внутри блока алгоритм использует турнирный отбор, скрещивание OX1,
обмен двух городов или инверсию отрезка и элитизм. Каждый маршрут представляет
перестановку городов; длина включает возвращение в начальный город:

\[
L(\pi)=\sum_{i=0}^{N-1}d_{\pi_i,\pi_{(i+1)\bmod N}},
\]

где \(N\) означает число городов, \(d_{a,b}\) — расстояние между городами,
а \(\pi\) — порядок обхода.

В одном раунде разные сервисы работают параллельно. После получения ответов
координатор выбирает лучший маршрут и передаёт его островам в следующем
блоке. Сервис вставляет мигранта вместо худшего маршрута, если мигрант короче.
Координатор хранит популяции и передаёт их между блоками: сервис не хранит
состояние предыдущих запросов.

Номер поколения в окне равен минимуму завершённых поколений по островам.
Он не учитывает работу незавершённых запросов. Средняя длина отражает последние
полученные популяции, график показывает точки после завершения раундов.
Лимит поколений действует на каждый остров; последний блок может быть короче.
Нулевой лимит означает поиск до нажатия «Стоп».

При фиксированном зерне каждый остров получает последовательность зерён,
которая зависит от его номера и блока, поэтому перенос между сервисами
не меняет задание. Число потоков задаёт локальный параллелизм каждого сервиса;
значение 0 разрешает использовать все доступные ядра.

## Сетевые ошибки

Координатор обрабатывает отказ соединения, таймаут, HTTP-ошибку, ошибочный JSON
и недопустимый результат. Он проверяет перестановки, пересчитывает длину
маршрута и сверяет статистику с возвращённой популяцией.

При ошибке координатор отключает адрес до следующего запуска поиска.
В следующем раунде он передаёт его остров оставшемуся сервису, сохранив
последнюю полученную популяцию. К одному сервису координатор отправляет блоки
последовательно. Если отказали все сервисы, окно показывает ошибку,
а найденный маршрут остаётся на экране. Новый «Старт» снова проверяет все адреса.

Таймаут действует на один запрос. При отмене HTTP-запроса сервис получает
`RequestAborted` и прекращает вычисления. Если ответ не дошёл до координатора,
тот не учитывает этот блок как выполненный.

Один экземпляр сервиса выполняет один блок одновременно. На дополнительный
запрос он отвечает HTTP 503. Неверные параметры получают HTTP 400 с описанием
ошибки. Сервис ограничивает запрос 32 МиБ, матрицу 512 городами, популяцию
10 000 маршрутами и блок 1 000 поколениями. Дополнительные пределы:
\(N\cdot P\leq2\,000\,000\) и
\((N+2T)\cdot P\cdot G\leq100\,000\,000\), где \(P\) — размер популяции,
\(T\) — размер турнира, \(G\) — число поколений в блоке.
При превышении уменьшите популяцию или число поколений в блоке.

## API и проверки

`GET /health` возвращает `{"status":"ok"}`.

`POST /api/batches` принимает `BatchRequest`: матрицу расстояний, параметры
алгоритма, число поколений, необязательную популяцию и мигранта.
В `BatchResponse` сервис возвращает популяцию, лучший маршрут, его длину
и историю каждого поколения блока. Контракты находятся в `Contracts.cs`.

Сценарные тесты используют `WebApplicationFactory<Program>` и xUnit fixtures
по [примеру из задания](https://timdeschryver.dev/blog/how-to-test-your-csharp-web-api#a-simple-test-using-xunit-and-39-s-fixtures).
Они поднимают ASP.NET Core TestServer и обращаются к API через HTTP-клиент.
Для тестов не нужно запускать сервисы вручную.

Проверки включают валидные маршруты, миграцию и продолжение популяции,
повторяемость при фиксированном зерне, некорректные запросы, конкурентные
запросы, сетевые отказы и отмену. Сквозные сценарии запускают две отдельные
копии приложения сервиса и проверяют работу координатора, перенос острова
после отказа и поиск без элитизма.
